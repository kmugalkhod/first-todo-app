Product review · 2 August 2026

Build a focused task product first.

The research describes a complete Todoist-like ecosystem. Our first release should recreate its durable core: fast capture, a reliable task model, useful daily views, and a calm interface. Collaboration, paid entitlements, external sync, AI, desktop/mobile clients, and automation follow only after that foundation works.

Build now — MVP

Personal task management

Inbox, Today, projects, sections, tasks and sub-tasks; priority, labels, scheduling, search, keyboard-first capture and a list view.

Build next

Planning & collaboration

Recurring rules, filters, board view, task detail, comments, sharing, assignments, reminders and activity history.

Deliberately defer

Platform & ecosystem

Calendar OAuth/sync, notifications, AI, automation/webhooks, billing, teams, audit/security controls, native apps and extensions.

Non-negotiable modelling choices

  • Date ≠ deadline. A scheduled work date and a hard finish boundary are separate fields; defer deadline until a paid-tier model exists if plans are required.
  • Duration ≠ time tracking. Expected effort supports later calendar blocking; it must not imply a running timer.
  • One assignee. If collaboration arrives, retain clear ownership and use sub-tasks for joint work.
  • Recurrence is a rule, not copied tasks. Design it only after completion semantics and time zones are stable.
  • Projects own tasks. Sections organise project work; labels cut across projects; parent/child tasks remain in one project.

Scope guardrails

  • Do not copy Todoist’s subscriptions, brand, screenshots, proprietary parser, or integrations; use the report as a capability reference.
  • Do not build teams, billing or roles until personal task CRUD is persisted and observed in real use.
  • Do not promise offline sync, OAuth calendar sync, push reminders, AI extraction or webhooks without their operational infrastructure.
  • Mobile web is a responsive companion for this project; native widgets, extensions and desktop global shortcuts are separate products.
  • Confirm plan entitlements only when monetisation becomes in scope; the report identifies inconsistencies in external pricing documentation.

Decision needed before Phase 1

Choose the first release target

My recommendation: a single-user, authenticated, responsive web application with persistent data. It gives us a real product path without prematurely modelling collaboration or paid plans.
